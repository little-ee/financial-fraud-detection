07 Autoencoder Incremental Value Analysis¶

This notebook evaluates whether the Autoencoder anomaly detector adds useful information beyond the supervised Random Forest model. Since the Random Forest already performs very strongly on PaySim, the Autoencoder should only be considered useful if it captures fraud cases missed by the supervised model without introducing excessive additional false positives.

The goal is not to prove that the Autoencoder outperforms the Random Forest. Instead, the goal is to test whether the Autoencoder provides a complementary anomaly signal.

If the Autoencoder does not capture additional fraud beyond Random Forest, it should be treated only as an experimental monitoring signal rather than a hard decision rule.

Main research question: Does the Autoencoder capture fraudulent transactions that the supervised Random Forest model misses?

def evaluate_binary_predictions(y_true, y_pred, score=None, model_name="Model"):
    tn, fp, fn, tp = confusion_matrix(y_true, y_pred, labels=[0, 1]).ravel()

    metrics = {
        "model": model_name,
        "accuracy": accuracy_score(y_true, y_pred),
        "precision": precision_score(y_true, y_pred, zero_division=0),
        "recall": recall_score(y_true, y_pred, zero_division=0),
        "f1": f1_score(y_true, y_pred, zero_division=0),
        "tn": tn,
        "fp": fp,
        "fn": fn,
        "tp": tp,
    }

    if score is not None:
        try:
            metrics["roc_auc"] = roc_auc_score(y_true, score)
        except ValueError:
            metrics["roc_auc"] = np.nan
        try:
            metrics["pr_auc"] = average_precision_score(y_true, score)
        except ValueError:
            metrics["pr_auc"] = np.nan

    return metrics

def load_saved_metrics_if_exists(path, report_name):
    if path.exists():
        print(f"Loaded saved {report_name}: {path}")
        return pd.read_csv(path)
    print(f"Warning: saved {report_name} not found at {path}")
    return None


def get_metric_from_row(row, metric):
    aliases = {
        "pr_auc": ["pr_auc", "average_precision"],
        "roc_auc": ["roc_auc"],
        "precision": ["precision"],
        "recall": ["recall"],
        "f1": ["f1", "f1_score"],
        "tn": ["tn"],
        "fp": ["fp"],
        "fn": ["fn"],
        "tp": ["tp"],
    }
    for column in aliases.get(metric, [metric]):
        if column in row.index:
            return row[column]
    return np.nan


def create_consistency_check_df(notebook_metrics, saved_metrics_df, metrics_to_compare):
    if saved_metrics_df is None or saved_metrics_df.empty:
        return None

    saved_row = saved_metrics_df.iloc[0]
    rows = []
    for metric in metrics_to_compare:
        notebook_value = notebook_metrics.get(metric, np.nan)
        saved_value = get_metric_from_row(saved_row, metric)
        rows.append(
            {
                "metric": metric,
                "notebook07_value": notebook_value,
                "saved_report_value": saved_value,
                "absolute_difference": abs(notebook_value - saved_value)
                if pd.notna(notebook_value) and pd.notna(saved_value)
                else np.nan,
            }
        )
    return pd.DataFrame(rows)

9. Compare RF-Only, AE-Only, and RF OR AE¶

The OR rule is intentionally aggressive. It estimates the maximum possible fraud capture if Autoencoder were used as an additional hard review trigger. If recall improves only slightly while false positives increase sharply, Autoencoder should not be used as a hard OR-rule.
