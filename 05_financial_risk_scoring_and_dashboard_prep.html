05 Financial Risk Scoring and Dashboard Preparation¶

This notebook converts the final supervised Random Forest model into a transaction-level risk scoring output. The Random Forest model is used as the primary decision model because it achieved the strongest supervised performance. The Autoencoder is not used as a hard decision rule because the incremental value analysis showed that it did not capture fraud cases missed by Random Forest and would introduce many extra false positives. Autoencoder outputs may be retained only as monitoring fields.

This is a post-transaction fraud detection and risk monitoring system because it uses transaction outcome and balance-related fields. The final risk score should be interpreted as a model-based fraud risk score, not necessarily a perfectly calibrated probability.

10. Add Optional Autoencoder Monitoring Fields¶

Autoencoder is included only as a monitoring field. It is not used as a hard rule because notebook 07 showed it did not add incremental fraud-capture value beyond Random Forest.

In [10]:
ae_monitoring_added = False

if AUTOENCODER_TEST_ERRORS_PATH.exists():
    ae_errors_df = pd.read_csv(AUTOENCODER_TEST_ERRORS_PATH)
    error_column_candidates = [
        "reconstruction_error",
        "anomaly_score",
        "ae_reconstruction_error",
    ]
    ae_error_column = next(
        (column for column in error_column_candidates if column in ae_errors_df.columns),
        None,
    )

    if ae_error_column is None:
        print(
            "Warning: Autoencoder test errors file exists but no reconstruction "
            "error column was found. Skipping AE monitoring fields."
        )
    elif len(ae_errors_df) != len(risk_df):
        print(
            "Warning: Autoencoder test error length does not match risk_df. "
            f"AE rows: {len(ae_errors_df)}, risk rows: {len(risk_df)}. "
            "Skipping AE monitoring fields."
        )
    else:
        ae_threshold = None
        if AUTOENCODER_THRESHOLD_PATH.exists():
            ae_threshold_metadata = load_json(AUTOENCODER_THRESHOLD_PATH)
            ae_threshold = ae_threshold_metadata.get("threshold")
        else:
            print("Warning: Autoencoder threshold file not found. Flag will be skipped.")

        risk_df = add_autoencoder_monitoring_columns(
            risk_df=risk_df,
            ae_reconstruction_error=ae_errors_df[ae_error_column].to_numpy(),
            ae_threshold=ae_threshold,
        )
        ae_monitoring_added = "ae_reconstruction_error" in risk_df.columns
        print("Autoencoder monitoring fields added successfully.")
else:
    print(
        "Warning: Autoencoder test reconstruction errors file not found. "
        "Skipping AE monitoring fields."
    )

print(f"AE monitoring added: {ae_monitoring_added}")

15. Final Summary¶

The final system uses Random Forest as the primary decision model. The selected threshold was chosen on validation data only, and test performance is reported once using the selected threshold. The transaction-level output is ready for dashboard or application use.

Autoencoder is retained only as monitoring, not as a hard OR-rule. This remains a post-transaction risk monitoring system because it uses balance-related transaction outcome fields.

The final risk score should be interpreted as a model-based fraud risk score, not necessarily a perfectly calibrated probability.
